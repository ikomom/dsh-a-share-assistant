## 0. 一句话结论（先看这个）

| 结论 | 取值 |
|---|---|
| K 线必填参数 | `secid` `fields1` `fields2` `klt` `fqt` `beg` `end`（**缺任何一个都 `rc:102` / `data:null`**） |
| `ut` | **可省略，实测不影响任何返回**（与最常见博客写法相反） |
| `lmt` | **只在 `beg` 为非 0 日期时生效**；`beg=0` 时 `lmt` 被忽略，返回全量 |
| `fqt` | 必填；`0`=不复权、`1`=前复权、`2`=后复权；省略或给 `3` 都是 `rc:102` |
| `beg`/`end` | 只接受 `YYYYMMDD`；毫秒戳和 `YYYY-MM-DD` 均失败（后者会被当成非法值→全量返回） |
| 日线深度 | 600519 一次拿到 **6012 根**（2001-08-27 起，`dktotal=6012`），`lmt` 给 50000 不限 |
| 分钟线深度 | `klt=1` 只有**最近 1 个交易日 240 根**（`lmt` 无效）；`klt≥5` 约 **1488 根上限（≈31 个交易日）** |
| trends2 `ndays` | **实测被忽略**：`ndays=1/2/3/4/5` 五次请求返回**字节完全相同**的同一份数据；`ndays=10` 直接 `rc:102` |
| trends2 点数 | 240 或 241 个点/日（09:30–15:00，**无 09:15/09:25 集合竞价点**，**无 15:00 之后点位**） |
| K 线列含义 | 日期,开,收,高,低,成交量(手),成交额(元),振幅%,涨跌幅%,涨跌额,换手率% |

## 2. 端点 1：历史 K 线（含分钟）

`https://push2his.eastmoney.com/api/qt/stock/kline/get`

### 2.1 URL 模板（可直接复制运行）

```
https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=1.600519&fields1=f1,f2,f3,f4,f5,f6&fields2=f51,f52,f53,f54,f55,f56,f57,f58,f59,f60,f61&klt=101&fqt=1&beg=0&end=20500101&lmt=120
```

实测该 URL 返回 `rc:0`、600519 全部 6012 根日 K（`lmt=120` 因为 `beg=0` 被忽略，见 2.3）。

### 2.2 参数表（必填性=实测判定）

| 参数 | 必填 | 类型 | 取值 | 默认行为 | 实测结果（证据） |
|---|---|---|---|---|---|
| `secid` | **是** | 字符串 | `市场前缀.代码`，如 `1.600519` | 无 | 省略 → `{"rc":102,...,"data":null}`；`secid=abc` → `rc:102`；`secid=600519`（无前缀）→ `rc:102`（`out\p1.log` H3/H4/H5） |
| `fields1` | **是** | 逗号串 | `f1,f2,f3,f4,f5,f6` | 无 | 省略（保留 fields2）→ `rc:102`（I1） |
| `fields2` | **是** | 逗号串 | `f51..f61` | 无 | 省略（保留 fields1）→ `rc:102`（I2）；两个都省略 → `rc:102`（I3） |
| `klt` | **是** | 整数 | `1`/`5`/`15`/`30`/`60`/`101`/`102`/`103` | 无 | `klt=999` → `rc:100`（`data:null`，注意是 100 不是 102）（H1） |
| `fqt` | **是** | 整数 | `0` / `1` / `2` | 无 | 省略 → `rc:102`（E4）；`fqt=3` → `rc:102`（E5） |
| `beg` | **是** | 字符串 | `0` 或 `YYYYMMDD` | 无 | 完全省略 beg（只给 lmt）→ `rc:102`（F1） |
| `end` | **是** | 字符串 | `YYYYMMDD`，常用 `20500101` | 无 | F1 中同时省略 end 也失败 |
| `lmt` | **否** | 整数 | 如 `1`/`8`/`120`/`50000` | 无（不给则按 beg/end 全量） | `lmt=8` 单独用无效（F2）；`beg=20250101&end=20500101` 不给 lmt 与给 `lmt=8` 返回**完全相同**的 421 行（F3/F4） |
| `ut` | **否** | 字符串 | `fa5fd1943c7b386f172d6893dbfba10b` 等 | 无 | 删除 `ut` 后**返回内容与带 ut 完全一致**（见 2.4） |
| `iscr` | 未核实 | — | — | — | 本端点未测 |
| `rtntype` | 未核实 | — | — | — | 本端点未测 |
| `_`(时间戳防缓存) | 未核实 | — | — | — | 本端点未测 |

### 2.3 `lmt` 与 `beg` 的相互作用（重点，三 / 四种情况都实测）

| 情况 | 请求 | 返回条数 | 证据 |
|---|---|---|---|
| ① 只有 `lmt=8`，无 `beg`/`end` | `...&klt=101&fqt=1&lmt=8` | **报错** `rc:102, data:null` | p1 F1 |
| ② `lmt=8&beg=0&end=20500101` | `...&beg=0&end=20500101&lmt=8` | **6012 条**（全量，lmt 被忽略） | p1 F2 |
| ③ `lmt=8&beg=20250101&end=20500101` | 同左 | **421 条**（区间内全量，lmt 仍被忽略） | p1 F3 |
| ④ `beg=20250101&end=20500101`（不给 lmt） | 同左 | **421 条**（与③逐字节相同，均为 36637 字节） | p1 F4 |
| ⑤ `lmt=1&beg=0&end=20500101` | 同左 | **6012 条**（再次确认 lmt 无效） | p1 F5 |
| ⑥ `lmt=50000&beg=0&end=20500101`（`klt=101`） | 同左 | **6012 条**（`dktotal=6012`，无 10000 之类截断） | p1 C3 |

**结论（实测）**：用 `fqt=1&klt=101&beg=0&end=20500101` 时 `lmt` 完全不起作用；要用 lmt 取"最近 N 根"，本批实测**没有**得到成功样例——
`lmt=8&beg=0`、`lmt=8&beg=20250101`、`lmt=1&beg=0` 三种写法都被忽略。

**未核实/推断**：`lmt` 究竟在什么条件下生效未核实。本次唯一疑似与条数有关的观测是 `klt=1&lmt=120` 返回 240 条、`lmt=50000` 也返回 240 条（见 2.6），但那是分钟线的单日上限，不是 lmt 生效。

### 2.4 `ut` 是否必填

- 带 ut：`...?secid=1.600519&ut=fa5fd1943c7b386f172d6893dbfba10b&fields1=...&klt=101&fqt=1&beg=0&end=20500101&lmt=5`
  → `http 200, bytes=511005, rc=0, dktotal=6012`
- 去掉 ut：`...?secid=1.600519&fields1=...&klt=101&fqt=1&beg=0&end=20500101&lmt=5`
  → `http 200, bytes=511005, rc=0, dktotal=6012`，`data.keys=["code","market","name","decimal","dktotal","preKPrice","klines"]`，首尾行完全相同
- 原始片段（去 ut 那次）：
  `{"rc":0,"rt":17,"svr":177617933,"lt":1,"full":0,"dlmkts":"","dsc":"0","data":{"code":"600519","market":1,"name":"贵州茅台","decimal":2,"dktotal":6012,"preKPrice":-313.3,"klines":["2001-08-27,-312.68,-312....`

**结论**：`ut` **可省略**。（证据：`out\p1.log` A1 vs B1；两个 URL 唯一差异就是 `ut=...&`）

### 2.5 响应结构与 K 线列语义（实测确认）

顶层结构（`klt=101`，600519）：

```json
{"rc":0,"rt":17,"svr":177617938,"lt":1,"full":0,"dlmkts":"","dsc":"0",
 "data":{"code":"600519","market":1,"name":"贵州茅台","decimal":2,
         "dktotal":6012,"preKPrice":-313.3,
         "klines":["2001-08-27,-312.68,-312.47,-312.03,-313.01,406318,1410347000.00,-0.31,0.26,0.83,56.83", ...]}}
```

| 顶层字段 | 实测含义 |
|---|---|
| `rc` | 0 = 成功；100 = 参数合法但标的/周期无法提供；102 = 参数缺失或语法非法 |
| `rt` | 返回类型标识（kline 成功时为 17，错误时为 1） |
| `svr` | 后端节点编号（同 URL 多次请求会变，如 177617925/177617938/177617942） |
| `lt` / `full` / `dlmkts` / `dsc` | 实测恒为 `1` / `0`（错误时 `full=1`）/ `""` / `"0"`，语义未核实 |
| `data` | 失败时恒为 `null` |

`data` 字段：

| 字段 | 实测含义 |
|---|---|
| `code` / `market` | 与请求 `secid` 拆开的代码/市场前缀（`1.600519` → `"code":"600519","market":1`） |
| `name` | 标的中文名（`"贵州茅台"`） |
| `decimal` | 价格小数位（600519=2、510300=3、港股腾讯=3、美股 AAPL=3） |
| `dktotal` | 该标的该周期的**总根数**（日线 6012；与本次返回的 klines 长度可能不同，见 2.3） |
| `preKPrice` | **= 首行的（收盘 − 涨跌额）**，即首根 K 线的参考前收 |
| `klines` | 字符串数组，每行逗号分隔 |

**K 线每列顺序与含义（实测确认）**

| 序号 | 含义 | 单位 | 证据 |
|---|---|---|---|
| 0 | 日期 | `YYYY-MM-DD`（分钟线为 `YYYY-MM-DD HH:mm`） | 全量样例 |
| 1 | 开盘 | 元 | `open` |
| 2 | 收盘 | 元 | 用 `[9]=收−前收` 反推前收 = `preKPrice`，600519/000001/000300/510300 全部成立 |
| 3 | 最高 | 元 | (高−低)/开 = `[7]`，见下 |
| 4 | 最低 | 元 | 同上 |
| 5 | 成交量 | **手** | 000001：`1523165 手 × 100 = 1.523 亿股`，换手率 0.78% → 流通股 195.3 亿股，与平安银行量级相符 |
| 6 | 成交额 | **元** | 510300：`3962899774 元 ÷ 8467983 手 = 467.99 元/手 = 4.68 元/股`，与当日 4.68 元价格一致 |
| 7 | 振幅 | % | 多行实测 `(高−低)/开×100`：510300 09-02 `(4.654−4.601)/4.650=1.14`↔报告 `1.13`（舍入）；000001 09-02 `(11.74−11.60)/11.67=1.20`↔报告 `1.20`；600519 分钟线 09:31 `(1256.13−1246.00)/1250.01=0.81`↔报告 `0.81` |
| 8 | 涨跌幅 | % | `(收−preKPrice)/preKPrice×100`：600519 fqt=0 首行 `(35.55−31.39)/31.39=13.25`↔报告 `13.25`；000001 09-01 ↔ `1.74`；000300 09-01 ↔ `-0.30` |
| 9 | 涨跌额 | 元 | `收 − preKPrice`：600519 `35.55−31.39=4.16`↔报告 `4.16` |
| 10 | 换手率 | % | `成交量(手)×100 ÷ 流通股`：000001 09-01 `1523165×100/(0.78/100)=195.3 亿股`，与 09-02 反推的 193.97 亿股一致 |

**异常点（实测，如实记录）**：
- `[7]` 振幅在**返回数组的第一行**不符合 `(高−低)/开`：600519 fqt=0 首行报告 `15.71`，而 `(37.78−32.85)/34.51(开)=14.29`；改用 `(37.78−32.85)/31.39(preKPrice)=15.71` 才吻合。510300 首行报告 `0.83`，用 `(4.705−4.666)/4.683(开)=0.83` 吻合，用 preKPrice 则不相符。**首行口径未核实。**
- `[8]` 涨跌幅在价格为负数（`fqt=1`）时符号不可靠：600519 `fqt=1` 首行报告 `0.26%`，而 `(收−preKPrice)/preKPrice×100 = (-312.47+313.3)/(-313.3)×100 = -0.26%`，符号相反。**推断**：前复权为负数时该字段不可用（这是推断，未核实其内部公式）。

### 2.6 klt 深度边界（`lmt` 给大值实测）

| `klt` | 请求 | 返回根数 | 首行 | 末行 | 覆盖 | 证据 |
|---|---|---|---|---|---|---|
| `1` | `lmt=50000&beg=0&end=20500101` | **240** | `2026-09-24 09:31` | `2026-09-24 15:00` | **仅最近 1 个交易日** | p1 C1 |
| `1` | `lmt=120&beg=20260901&end=20500101` | **240** | 同上 | 同上 | 同上（响应 21068 字节，与上一条完全相同） | p2 D2 |
| `5` | `lmt=50000&beg=0&end=20500101` | **1488** | `2026-08-13 09:35` | `2026-09-24 15:00` | 约 31 个交易日 | p1 C2 |
| `15` | `lmt=50000&beg=0&end=20500101` | **496** | `2026-08-13 09:45` | `2026-09-24 15:00` | 约 31 个交易日 | p1 C4 |
| `101` | `lmt=50000&beg=0&end=20500101` | **6012** | `2001-08-27` | `2026-09-24` | 全历史，无截断 | p1 C3 |

**结论**：
- **1 分钟与 5 分钟深度明显不同**：1 分钟只有最近 1 个交易日 240 根，给 `lmt=120` 或 `lmt=50000` 都是同样的 240 根（响应字节数完全相同），**`lmt` 对 1 分钟无效**。
- 5 分钟/15 分钟一次约 1488 / 496 根 ≈ 31 个交易日，`lmt=50000` 也无法更深（`1488≈31×48`、`496≈31×16`）。
- 日线可拿全历史（600519 上市至今 6012 根下单次返回），未观察到 10000 根之类上限。

| 场景 | 请求要点 | HTTP | 原始返回（完整） |
|---|---|---|---|
| 缺 `secid` | `ut=...&fields1=...&fields2=...&klt=101&fqt=1&beg=0&end=20500101&lmt=5` | 200 | `{"rc":102,"rt":1,"svr":177617925,"lt":1,"full":1,"dlmkts":"","dsc":"0","data":null}` |

| `secid=600519`（无前缀） | 同上参数 | 200 | `{"rc":102,"rt":1,"svr":177617932,"lt":1,"full":1,"dlmkts":"","dsc":"0","data":null}` |
| 缺 `fqt` | 去掉 `fqt` | 200 | `{"rc":102,"rt":1,"svr":177617925,"lt":1,"full":1,"dlmkts":"","dsc":"0","data":null}` |
| `fqt=3` | 非法枚举 | 200 | `{"rc":102,"rt":1,"svr":177617926,"lt":1,"full":1,"dlmkts":"","dsc":"0","data":null}` |
| 缺 `fields1`/`fields2` | 分别省略 | 200 | 同上形态的 `rc:102` |

**注意**：所有错误都是 **HTTP 200**，必须看 `rc` 才能判断成败。`rc:100` = 标的不存在/周期不支持；`rc:102` = 参数问题。

### 2.8 坑与注意事项（均有实测支撑）

1. **`beg` 与 `end` 至少要显式出现**，只给 `lmt` 会 `rc:102`（F1）。
2. **`beg=0` 会让 `lmt` 失效**，返回全量 6012 条 511 KB——想"只要最近 N 根"不能这么写（F2/F5）。
3. **`beg` 给错格式（`2023-08-01`、毫秒戳）行为不一致**：横线格式静默返回全量（危险，容易被误当成"限制了区间"），毫秒戳直接 `rc:102`。**只用 `YYYYMMDD`**。
4. **`fqt` 不能省**，且省了报 `rc:102` 而不是回落到默认值。
5. **`fqt=1` 早期数据是负数**（600519 首行开 `-312.68`），`preKPrice` 也是 `-313.3`；`[7]`振幅、`[8]`涨跌幅此时不可用（见 2.5 异常点）。
6. 分钟线响应体量不小（1 分钟 21 KB / 5 分钟 132 KB），且 1 分钟只给 1 天，做长周期分钟回测要自己循环拼接（未实测循环拼接）。
7. `data.dktotal` 与 `klines.length` 不是一回事：`dktotal=6012` 而 `end=20200110` 那次只返回 4386 条（E1/E2/E3）。

| 12:04:5x | 同批探测中，前 9 次 `stock/get`/`trends2` 成功，随后**第一个 kline 请求失败** | `out\p3.log` M1：`FETCH_ERROR: fetch failed` |
| 12:05 起 | `kline/get` **持续性失败**：push2his、push2delay、直连 IP（117.184.38.143）全部同样失败 | p4/p5/p6/p8 |
| 12:10 – 12:14 | 3 分钟（间隔 30 秒 × 6 次）反复重试，**6/6 全部失败** | `out\p9.log` |
| 12:10 – 12:14 | **对照端点仍正常**：`trends2`（push2 与 push2his 两个主机）始终 `rc:0`；`stock/get` 在 12:11–12:12 有成功、12:14 失败 | p8/p9/p10 |

### 7.2 失败的原始错误（不是 HTTP 状态码）

```
FAIL kline-try1 fetch failed/UND_ERR_SOCKET      # cause: SocketError: other side closed
FAIL kline-min-lmt1 fetch failed/UND_ERR_SOCKET
FAIL kline-other-secid fetch failed/UND_ERR_SOCKET
OK   his-trends2-control http=200 bytes=7018
FAIL push2-get-control fetch failed/UND_ERR_SOCKET
```
证据：`out\p7.log`（打印了 `e.cause.code`）、`out\p9.log`、`out\probe10.json`。

### 7.3 排除的因素（均实测排除）

| 假设 | 实测 | 结论 |
|---|---|---|
| 域名/主机故障 | `https://push2his.eastmoney.com/` → `http 404`（TCP/TLS 通）；`push2his` 的 `trends2` 路径 `http 200` | 排除主机级故障（p6/p7/probe10） |
| 本机 DNS | `Resolve-DnsName push2his.eastmoney.com` → CNAME `push2hisipv6.trafficmanager.cn` → A `117.184.38.143`；`push2` → `101.226.30.206`（均正常解析） | 排除 DNS |
| 请求头差异 | 去掉 `User-Agent`/`Referer` 自定义头后**同样失败** | 排除请求头（p8 `noheader-kline`） |
| 源 IP 被封 | 换另一个出口 IP 的机器/网络重试 → 同样 `UND_ERR_SOCKET` | 排除单 IP 封禁 |
| 响应体过大 | 最小请求（`lmt=1`，响应约 200 字节）也失败 | 排除响应体大小（probe10） |
| 参数问题 | 换 `secid`（`0.000001`）、换 `lmt`、换 `klt` 均失败，且此前相同参数全部成功 | 排除参数 |
| 代理干扰 | 脚本在发请求前显式删除 `https_proxy`/`HTTP_PROXY`/`NODE_USE_ENV_PROXY`，且成功请求与失败请求在同一进程配置下交替出现 | 排除代理 |

### 7.4 结论（实测）

- 现象：在累计约 60 次成功请求后，**`/api/qt/stock/kline/get` 路径开始被服务端直接关闭 TCP 连接（`UND_ERR_SOCKET: other side closed`）**，持续至少 **10 分钟**、跨主机（push2his / push2delay / 直连 IP）、跨参数、跨源 IP 均未恢复。
- 同一时间段内 `/api/qt/stock/trends2/get` 仍稳定返回 200，`/api/qt/stock/get` 时好时坏。
- 因此**这不是"IP 限流"，更像按接口路径/后端实例触发的风控或熔断**。
- **未核实**：封禁的确切触发条件（累计请求数？请求速率？特定参数组合？）、持续时长、是否与 UA/Referer 有关。
- **给使用者的建议（基于实测，不是推断）**：把请求分散、避免短时间集中打 `kline/get`；一旦开始出现 `fetch failed / UND_ERR_SOCKET`，不要靠重试解决（实测重试 6/6 失败），应改用 `trends2`/`stock/get` 等仍可用的端点，或等待较长时间再试。

## 8. 「实测确认」与「未核实 / 推断」分节

### 8.1 实测确认（有原始 URL + 返回值）

1. kline 必填参数为 `secid/fields1/fields2/klt/fqt/beg/end`，缺任一 → `rc:102, data:null`。
2. `ut` 可省略，返回内容一致（511005 字节逐字段一致）。
3. `lmt` 在 `beg=0` 或 `beg=20250101` 两种写法下**都被忽略**；`lmt` 单独使用（无 beg/end）→ `rc:102`。
4. `fqt` 必填：`0`=不复权（首行 34.51）、`1`=前复权（首行 -312.68）、`2`=后复权（2020-01-10 收 5893.00）；省略或 `3` → `rc:102`。
5. `beg`/`end` 只接受 `YYYYMMDD`：毫秒戳 → `rc:102`；`2023-08-01` → 不报错但返回全量。
6. K 线列序与语义：日期,开,收,高,低,量(手),额(元),振幅%,涨跌幅%,涨跌额,换手率%（用 4 只标的 × 多行算术核对）。
7. 日线深度：600519 一次 6012 根到 2001-08-27；`lmt=50000` 返回 6012 根，无 10000 截断。
8. 分钟线深度：`klt=1` 仅 240 根（最近 1 日）；`klt=5` 1488 根；`klt=15` 496 根（跨 2026-08-13 ~ 2026-09-24）。
9. trends2：`ndays` 取值 1–5 返回内容完全相同（18403 字节 / 241 条 / 仅 2026-09-24），加随机参数破坏缓存后复核结果不变；`ndays=10` → `rc:102`。
10. trends2 时间范围：09:30 – 15:00，共 241 点，**无 09:15/09:25，也无 15:00 之后**。
11. trends2 的 `fields2` 必填（省略 → `rc:102`）；`ut` 可省略。
12. stock/get：`fields` 可省略（返回 60 个默认字段，含 `f80` 交易时段）；`secids` 批量写法在本端点失败（`rc:102`），批量需走 `ulist.np`。
13. stock/get 字段缩放：×100（`f43=123700` = 1237.00），且 `f43/f44/f45/f46/f47/f48/f168/f169/f170/f171` 与同日 kline 完全对应。
14. secid 前缀：`1.` 沪市股票/科创板/沪 ETF/沪指数；`0.` 深市股票/创业板/深指数/北交所；`116.` 港股；`105.` 美股；`0.00700` 港股 → `rc:100`。
15. 退市/已切换标的：`rc:0` + `klines:[]` + `name` 带"(已切换)"；不存在的代码：`rc:100`。
16. 逐笔 `details/get` 可用，`pos=-10` 返回 10 笔，且含 15:00 后的成交（15:00:02 / 15:05 / 15:06 / 15:08 / 15:29）。
17. 限流：累计约 60 次成功后 `kline/get` 出现持续性 `UND_ERR_SOCKET: other side closed`（≥10 分钟、跨主机/跨 IP/跨参数），同期 `trends2` 正常。
18. 所有错误响应均为 **HTTP 200**，靠 `rc` 判别：`100`=标的/周期无效，`102`=参数错误。

### 8.2 未核实 / 推断（明确标注）

**未核实（没测或测了但结论不成立）：**
- `lmt` 在什么条件下真正生效（本次所有组合都被忽略）。
- trends2 的 `ndays` 语义（实测被忽略，是否本应返回多日数据未知）。
- trends2 `data` 的 `beticks` / `time` / `kind` / `type` / `status` / `preSettlement` 含义。
- trends2 第 7 列（`f58`）均价的确切公式。
- K 线 `[7]` 振幅在**返回数组第一行**的口径（`(高−低)/前收`？与其余行的 `(高−低)/开` 不一致，两个样本互相矛盾）。
- stock/get 的 `f49` `f50` `f55` `f62` `f71` `f78` `f84` `f85` `f86` `f92` `f103`–`f117` `f162` `f167` 等字段含义（仅 `f80` 确认）。
- `ulist.np` 的 `f2/f3/f12/f13/f14` 之外字段码；`ulist` 是否有条数上限。
- 逐笔 `details/get` 的第 4、5 列含义；`pos` 的取值范围与上限。
- `sse/get`（五档）：请求挂起无响应，**状态未知**。
- 是否有可用的**多日分时**端点。
- 停牌中（而非退市）股票的返回结构。
- `beg`/`end` 的边界行为（如 `beg` 晚于 `end`、`end` 给过去日期）未做系统测试；仅观测到 `end=20200110` 会正常截断。
- 各 `klt` 取值是否只有 `1/5/15/30/60/101/102/103`，未逐一枚举（只测了 1/5/15/101 成功，999 失败）。
- `iscr`、`invt`、`fltt`、`rtntype` 等参数未测。
- 分钟线 `klt=5` 的 1488 根是否为硬上限（只测了一次 `lmt=50000`）。

**推断（非实测结论，仅作参考）：**
- `f50` 量比、`f51`/`f52` 涨停/跌停、`f116`/`f117` 总/流通市值、`f162` 市盈率、`f167` 市净率：由数值量级与常见口径**推断**，未做对照实验。
- `beticks="33300|34200|54000|34200|41400|46800|54000"` **推断**为交易时段边界（09:15/09:30/…/15:00 的秒数），未核实。
- 北交所老代码（`4xxxxx`/`8xxxxx`）**推断**也用 `0.` 前缀，未核实。
