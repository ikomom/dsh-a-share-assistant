> **本文只写实测到的事实。** 每条结论后面都附「证据」＝实际请求 URL ＋ 观察到的原始输出片段/条数。
> 没测过的一律写 **「未核实」**，由实测结果做的解释写 **「推断（未核实）」**，绝不按记忆或常见博客填参数行为。

## 2. 当日分时：`minute/query`

### 2.1 URL 模板

```
https://web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600522
```

### 2.2 参数表

| 参数 | 必填 | 类型 | 取值 | 默认行为 | 实测结果 |
|---|---|---|---|---|---|
| `code` | 是 | string | `sh600522`（前缀+6位代码，见 §7） | 无 | 传 `sh600522` → 200，267 点。**未做缺参反例（未核实）** |

### 2.3 响应结构

```
code                              -> 0
msg                               -> ""
data.<code>.data.date             -> "20260924"          // 数据所属交易日
data.<code>.data.data             -> Array<String> 267   // 每行 4 个空格分隔字段
data.<code>.qt.<code>             -> Array(88)           // 快照，见 2.4
data.<code>.qt.market            -> Array(1)            // "时间|各市场状态" 字符串
data.<code>.qt.v_ff_<code>        -> Array(0)            // 本次为空
data.<code>.mx_price              -> {"price":"","mx":""} // 本次为空
```

**每行字段顺序（4 个，不是 5 个）**：`HHMM 价格 累计成交量(手) 累计成交额(元)`

证据（原始样例，截断）：
```json
{"code":0,"msg":"","data":{"sh600522":{"data":{"data":["0930 35.70 15424 55063680.00","0931 35.76 49349 176788596.07","0932 35.64 66221 236953034.60", ... ,"1529 34.80 1204092 4242082349.69","1530 34.80 1204258 4242660029.69"],"date":"20260924"}, ...
```

字段含义的**算术证据**（不是靠常识）：

- 第 3 列是**累计**量、第 4 列是**累计**额（单调递增，不是每分钟量）：
  `0930 35.70 15424 55063680.00` → `35.70 × 15424 × 100 = 55,063,680.00`，与第 4 列**分毫不差**。
- **没有均价字段**：`0931 35.76 49349 176788596.07` → `176788596.07 / (49349×100) = 35.8241`，而第 2 列是 `35.76`。若第 2 列是均价应等于 35.8241，故第 2 列是**该分钟最后成交价**，均价需要自己用 `额/(量×100)` 算。
- 单位是手/元：15:00 那行 `1500 34.80 1202576 4236806669.70`，与快照 `qt[6]=qt[36]="1202576"`（手）完全一致。

### 2.4 时间点范围（含"1530 到底是什么"）

实测 267 点 = **09:30–11:30（121 点）+ 13:00–15:00（121 点）+ 15:06–15:30（25 点）**。

- **不含集合竞价**：不存在 09:15 / 09:25 / 09:26 任何点，第一点就是 `0930`。
- `1300` 这一点是**占位重复**：`1130 35.04 756217 2676902940.94` 与 `1300 35.04 756217 2676902940.94` 三个字段完全相同。
- **15:01–15:05 没有点**，从 15:06 起重新出现，直到 1530。
  证据：`1500,1506,1507,1508,...,1529,1530`（15:01~15:05 缺失）
- **1530 不是"收盘价"这么简单**：15:06–15:30 这些点价格恒等于 15:00 收盘价 `34.80`，但累计量和累计额继续增加。
  证据：`1500 34.80 1202576 4236806669.70` → `1510 34.80 1203378 4239597629.69` → `1530 34.80 1204258 4242660029.69`
  这 25 个点对应的**盘后增量** = `1204258-1202576 = 1682 手`、`4242660029.69-4236806669.70 = 5,853,359.99 元 = 585.3360 万元`，
  而**同一响应的快照 `qt[58] = "585.3360"`** —— 完全吻合。
  → **实测确认**：`qt[58]` 就是这段盘后成交额（万元），15:06–15:30 的点是**盘后成交**（不是盘中数据）。
  → **推断（未核实）**：这段业务上属于盘后固定价格交易/盘后定价，具体业务名未从接口文案中得到确认。
  → **重要**：日线/分钟K线的成交量**不含**这 1682 手（见 §3.6）。

## 3. 分钟 K 线：`kline/mkline`

### 3.1 URL 模板

```
https://ifzq.gtimg.cn/appstock/app/kline/mkline?param=sh600522,m5,,320
```

### 3.2 `param` 格式（4 段，逗号分隔）与逐段实测判定

```
param=<code>,<周期>,<必须留空>,<条数>
```

| 段 | 含义 | 必填 | 实测取值 | 实测结果 |
|---|---|---|---|---|
| 1 | 代码 | 是 | `sh600522` | 缺整个 `param` → `{"code":-1,"msg":"param error","data":[]}` |
| 2 | 周期 | 是 | **m1 / m5 / m15 / m30 / m60 / m120 六个全部可用**；`day` 不可用 | `m1,m5,m15,m30,m60,m120` 均 200 且各返回 320 根；`day` → `{"code":-1,"msg":"param error","data":[]}`；`m7` → 同样 `param error` |
| 3 | **必须为空** | 是（必须留空） | `100` 或 `20260920` | **不报错但静默返回空数组**：`{"code":0,"msg":"","data":{"sh600522":{...,"m5":[],"prec":"35.78"}}}` ← 见 §10 坑 3 |
| 4 | 条数（上限） | 否 | `10` / `320` / `100000` | `10`→10 根；`320`→320 根；`100000`→**仍是 320 根**；**整个字段省略**（`param=sh600522,m5,,`）→ m5 返回 **482 根**（比 320 还多） |

### 3.3 各周期实际上限与覆盖范围（`count=100000` 实测）

| 周期 | 请求 100000 实际返回 | 覆盖区间（320 根时） |
|---|---|---|
| `m1` | **320 根** | `202609231342` → `202609241500`（约 1.3 个交易日） |
| `m5` | **320 根** | `202609161055` → `202609241500`（约 7 个交易日） |
| `m15` | **320 根** | `202608280945` → `202609241500` |
| `m30` | **320 根** | `202607311000` → `202609241500` |
| `m60` | **320 根** | `202606041030` → `202609241500` |
| `m120` | **320 根** | `202601291130` → `202609241500` |

**结论：`mkline` 的硬上限是每周期 320 根，与周期无关**（不是"周期越大给越多"）。
证据：`param=sh600522,m1,,100000` 响应 body 长度 23939 字节，与 `param=sh600522,m1,,320` 的 23939 **完全一致**；6 个周期逐个实测同为 320。

### 3.5 每行 8 个字段的顺序与含义

| 索引 | 含义 | 类型 | 我是怎么确认的 |
|---|---|---|---|
| `[0]` | 时间 `YYYYMMDDHHMM`（**12 位、无分隔符**） | string | 实测值长度恒为 12，如 `202609241500`，与分时接口的 `date=20260924` 对齐 |
| `[1]` | **开盘** | string(数字) | 用日K交叉验证：2026-09-24 日K `["2026-09-24","35.700","34.800","36.070","34.790","1202576.000"]`，而快照 `qt[5] 今开=35.70`、`qt[33] 最高=36.07`、`qt[34] 最低=34.79`、`qt[3] 最新价=34.80` —— 四个数逐一对应 `[1][2][3][4]` |
| `[2]` | **收盘** | string(数字) | 同上 |
| `[3]` | **最高** | string(数字) | 同上（`[3] ≥ max([1],[2])` 恒成立） |
| `[4]` | **最低** | string(数字) | 同上（`[4] ≤ min([1],[2])` 恒成立） |
| `[5]` | 成交量（**手**，带小数） | string(数字) | 见下方 §3.6 求和验证 |
| `[6]` | **恒为空对象 `{}`** | object | 6 个周期 × 320 根 = 1920 行，`Object.keys(row[6]).length === 0` 的行数 = 1920。含义**未核实** |
| `[7]` | 该周期成交量占股本比例（**万分比**，即"换手率 × 100"） | string(数字) | 见下方 §3.7 公式验证 |

#### 3.6 `[5]` 是"这一根的成交量(手)"的证据

- 把 `m1` 在 2026-09-24 的 241 根 `[5]` 求和 = **1202578.00 手**；分时接口 15:00 的累计量 = **1202576 手**；快照 `qt[6]` = **1202576 手**。差 2 手（四舍五入），量级完全对得上。
- 把 `m5` 同一天的 48 根求和 = **1202577.00 手**，同样只差 1 手。
- 反之，若按"累计量"解释，最后一根应等于 1202576，但单根 `[5]` 值远小于它（如 `40933.00`），故是**每根的量**，不是累计量。
- 且 241 根 m1 之和 = 15:00 的日累计量 → **K 线不含 15:06–15:30 的 1682 手盘后量**。

#### 3.7 `[7]` 是"万分比换手"的证据（逐行精确相等）

用快照里的总股本 `qt[72] = 3412949652` 计算 `[5]×100/3412949652×10000`：

| 行 | `[5]` | 响应里的 `[7]` | 计算值 |
|---|---|---|---|
| m5 `202609161055` | 40452.00 | `11.8525` | 11.8525 ✔ |
| m5 `202609161100` | 53761.68 | `15.7523` | 15.7523 ✔ |
| m30 `202607311000` | 1112523.33 | `325.9712` | 325.9712 ✔ |
| m30 `202607311030` | 376484.38 | `110.3106` | 110.3106 ✔ |
| m60 `202606041030` | 1695403.60 | `496.7561` | 496.7561 ✔ |
| m60 `202606041130` | 672084.17 | `196.9218` | 196.9218 ✔ |

→ 即 `[7] = 成交量(股) / 总股本 × 10000`。**未核实**：分母到底是总股本还是流通股本（600522 两者相等，无法区分），也不能排除是"流通股本"口径；若换成低流通占比的股票会看出差别。

### 3.8 省略第 4 段的实测行为

## 4. 日/周/月 K 线：`fqkline/get`（含复权）

### 4.1 URL 模板

```

https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600522,month,,,320,qfq

https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh600522,day,,,320,          ← 不复权（第 6 段留空，逗号要留）
```

### 4.2 参数表（`param` 共 6 段）

| 段 | 含义 | 必填 | 取值 | 默认行为 | 实测结果 |
|---|---|---|---|---|---|
| 1 | 代码 | 是 | `sh600522` / `sh600519` | — | 可用（§7） |
| 2 | 周期 | 是 | `day` / `week` / `month` | — | 三者均实测可用；`day` 时 320 根覆盖 `2025-06-09`→`2026-09-24` |
| 3 | 起始日期 | 否 | 留空 或 `2026-09-10`（**带连字符**） | 留空＝从最新往前取 | 填了生效：`sh600519,day,2026-09-10,2026-09-24,20,qfq` 只返回 11 行（区间内交易日数） |
| 4 | 结束日期 | 否 | 留空 或 `2026-09-24` | 留空＝到最新 | 同上；**不带连字符的格式未测（未核实）** |
| 5 | 条数 | 否 | `20` / `320` / `1000` / `100000` | 留空行为**未核实** | `1000`→**640 根**（被钳制）；`100000`→`{"code":0,"msg":"param error","data":[]}` |

**实测上限：`count` 最多 640 根**（要 1000 只给 640）。证据：`param=sh600522,day,,,1000,qfq` → `qfqday` 长度 640（body 43254 字节，首行 `2024-02-02`）；而 `param=sh600522,day,,,100000,qfq` → `param error`。
→ **注意数量级差别**：1000 被静默钳制到 640，100000 直接报错。要 640 以上必须自己分段。

### 4.3 响应结构：**键名随复权类型变化**

| `hfq` | `hfqday` |
| 留空 | `day` |
| `qfq` + **指数**（sh000001/sz399001） | 仍是 `day`（实测：传 `qfq` 不改变键名；原因未核实） |

其余同级键：`qt`、`mx_price`、`prec`、`version`。`version` 的**实测映射**：`qfq`→`"18"`、`hfq`→`"18"`、第 6 段留空→`"16"`（`version` 字段本身的含义未核实）。

### 4.4 复权：实测确认支持，且**前复权不是乘系数**

**结论 1：`fqkline/get` 支持 `qfq`（前复权）与 `hfq`（后复权），参数就是第 6 段。**

**结论 2：同一批日期上，`qfq` 与不复权是"相减"关系，不是"相乘"关系。**
600522、2025-06-09 起 4 个交易日，三份数据（`qfq` / 不复权 / `hfq`）：

| 日期 | 不复权收 | `qfq` 收 | 差值(不复权−qfq) | `hfq` 收 | 比值(hfq/不复权) |
|---|---|---|---|---|---|
| 2025-06-09 | 13.750 | 13.192 | **0.558** | 115.193 | 8.37767 |
| 2025-06-10 | 13.630 | 13.072 | **0.558** | 114.267 | 8.38349 |
| 2025-06-11 | 13.650 | 13.092 | **0.558** | 114.421 | 8.38249 |
| 2025-06-12 | 13.670 | 13.112 | **0.558** | 114.575 | 8.38149 |

- `qfq`：**差值恒定 0.558，比值不恒定**（0.95942 / 0.95906 / 0.95912 / 0.95918）→ 前复权在本区间表现为"减一个常数"。
- `hfq`：**比值近似恒定**，用两点解线性关系得 `hfq ≈ 7.7167 × 不复权 + 9.089`，代回第 3、4 行分别得 114.422 / 114.576，与实测 114.421 / 114.575 吻合到 0.001。
- **推断（未核实）**：0.558 是 2025-06 之后累计的每股现金分红；两个复权都是"分红/送转线性变换"，具体公式未从接口文案确认。
- **最新一根 `qfq` 与不复权完全相同**（2026-09-24：都是 `35.700/34.800/36.070/34.790/1202576.000`），而 `hfq` 最后一根是 `289.003/282.053/291.860/281.976/1202576.000` → **前复权的基准是最新交易日**（最新价不变）。

**结论 3：600519 那次对比"看不出复权" —— 原因不是不支持。**
`param=sh600519,day,2026-09-10,2026-09-24,20,qfq` 与同一区间不复权，返回的 11 行**逐字节完全相同**（`JSON.stringify` 相等 = true），首行都是 `["2026-09-10","1291.000","1285.130","1294.990","1282.000","18900.000"]`。
**推断（未核实）**：该区间内 600519 没有除权除息事件，所以前复权＝原值；**验证复权必须挑一个跨越除权日的区间**，用 600519 短区间对比会得出错误结论。（600522 的 2025-06 区间就能看出差别，因为其间有分红。）

**结论 4：长期前复权会出现负价（实测）。**
`param=sh600522,month,,,320,qfq` 共 287 根，最早三根：
```json
["2002-10-31","-0.165","-0.197","-0.112","-0.237","774339.490"]
["2002-11-29","-0.200","-0.155","0.025","-0.281","1664193.690"]
["2002-12-31","-0.172","-0.406","-0.152","-0.418","381928.640"]
```
2002–2004 段大量负值。→ **前复权数据不能假设为正数**；月线共 287 根（不是 320，因为 600522 2002-10 才上市，历史用尽）。
另有除权月的"断崖"样例：`["2026-07-31","59.840","28.520","59.870","27.020","58480418.000"]`（同一个月内开 59.84、收 28.52），**推断（未核实）**该月内发生了送转除权。

## 11. 坑清单（全部来自实测）

1. **`mkline` 上限 320 根，6 个周期全一样**——常见写法"要 1000 根"会被静默砍到 320，不报错，很容易以为自己拿到了 1000 根。
2. **`mkline` 的"周期"不支持 `day`**，`day` 要换 `fqkline/get` 或 `kline/kline`。
3. **`mkline` 的第 3 段必须留空**。填任何值（数字或日期）→ `code:0`、`msg:""`、数组为空。**只检查 `code` 会以为自己成功了**。
4. **`fqkline/get` 的日线上限是 640 根**；1000 被静默钳制到 640，100000 则直接 `param error`——**报错阈值和钳制阈值不是一回事**。
5. **`fqkline/get` 报参数错误时 `code` 仍是 `0`**（`{"code":0,"msg":"param error","data":[]}`），而 `mkline` 报同样的错是 `code:-1`。→ **必须同时校验 `code` 和 `msg`，并且判空数组。**
6. **数据键名随参数变化**：`qfq`→`qfqday`、`hfq`→`hfqday`、留空→`day`；指数和港股即使传 `qfq` 也仍叫 `day`。写死 `data[code].day` 的代码在传复权时会拿到 `undefined`。
7. **`minute/query` 的最后 25 个点是盘后成交**（15:06–15:30，价格恒为收盘价），其量和额**不计入日成交量**，而是单独放在快照 `qt[58]`（万元）。把 267 点当"连续竞价"做指标会算错。
8. **`minute/query` 没有集合竞价点**（无 0915/0925），**最先出现的是 0930**；且 `1300` 那一点与 `1130` 三个字段完全相同（占位）。
9. **`mkline` 的 `m1` 一天 241 根、没有 1300 那根**；`m5` 一天 48 根、没有 0930。想要和分时接口逐点对齐会差一根。
10. **`Content-Type` 是 `text/html`，body 却是 JSON**。别用 Content-Type 判断。
11. **不存在的代码返回 `code:0` + 空数组**，不报错。
12. **北交所（`bj`）K 线拿不到数据**；美股 `usAAPL` 这种写法只回 2 行垃圾数据。
13. **前复权可能出负价**（600522 月线 2002–2004 全是负值），且**前复权不是简单乘系数**（本次实测是同区间"减常数"）。写回测时不能假设价格恒正、也不能自己用比例还原。
14. **拿 600519 短区间对比复权会误判"接口不支持复权"**——区间内没有除权事件时 `qfq` 与不复权完全相同（实测 11 行逐字节相等）。要验证复权必须挑跨越除权日的区间。
15. **`qt` 的数组长度随市场不同**：沪市 88 / 北交所 87 / 港股 78 / 美股 73。硬编码 88 会越界或错位。
16. **分钟 K 线的时间格式是 12 位数字 `YYYYMMDDHHMM`，日线是带连字符的 `YYYY-MM-DD`**，两套格式别混用。
